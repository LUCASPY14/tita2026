I. Diagrama de Despliegue — Sistema Cantina Tita

Arquitectura
Infraestructura de producción: contenedores Docker sobre servidor Linux. El frontend (Nginx + React) recibe peticiones del navegador, el backend Django corre con Gunicorn, y los workers Celery procesan tareas asíncronas. Redis actúa como broker y caché. PostgreSQL es la base de datos central.

    SVC->>SVC: _actualizar_stock_y_costos(prod, cant, costo)
    SVC->>DB: UPDATE Stock.cantidad += cantidad
    SVC->>DB: INSERT MovimientoStock(COMPRA, INGRESO)
    SVC->>DB: INSERT CostoHistorico(costo_unit)
    SVC->>DB: UPDATE AlertaStock (si resuelve)
  end
  SVC->>DB: INSERT CuentaCorrienteProveedor(COMPRA)
  DB-->>SVC: Commit OK
  API-->>F: 201 {compra_id, monto_total}
  F-->>A: ✅ Compra registrada, stock actualizado

SEQ-06 · Secuencia — Ajuste de Inventario (Solicitar y Aprobar)

inventario
Flujo de doble paso: el usuario solicita un ajuste de inventario y el administrador lo aprueba o rechaza. Solo al aprobarse se modifica el stock real del sistema.
sequenceDiagram
  actor U as 👤 Usuario
  actor A as 👤 Admin
  participant F as Frontend
  participant API as Django API
  participant DB as PostgreSQL

  U->>F: Crea solicitud de ajuste
  F->>API: POST /api/v1/inventario/ajustes/
  API->>DB: INSERT AjusteInventario (PENDIENTE)
  API->>DB: INSERT DetalleAjuste[]
  DB-->>API: Ajuste creado
  API-->>F: 201 {ajuste_id, estado:PENDIENTE}
  F-->>U: ✅ Solicitud enviada para aprobación

  Note over A,DB: El Admin revisa la solicitud
  A->>F: Aprueba ajuste
  F->>API: POST /api/v1/inventario/ajustes/{id}/aprobar/
  API->>DB: BEGIN TRANSACTION
  API->>DB: UPDATE AjusteInventario.estado = APROBADO
  loop Por cada DetalleAjuste
    API->>DB: UPDATE Stock.cantidad (±cantidad)
    API->>DB: INSERT MovimientoStock(AJUSTE)
    API->>DB: UPDATE DetalleAjuste.movimiento_stock
  end
  API->>DB: Commit OK
  API-->>F: 200 {ajuste_id, estado:APROBADO}
  F-->>A: ✅ Ajuste aplicado al stock

SEQ-07 · Secuencia — Emisión de Factura Legal

contabilidad
Flujo de emisión de factura preimpresa para una carga de saldo o pago de almuerzo. El sistema calcula IVA automáticamente y vincula la factura al origen para evitar duplicados.
sequenceDiagram
  actor C as 🧑‍💼 Cajero
  participant F as Frontend
  participant API as Django API
  participant SVC as FacturacionService
  participant DB as PostgreSQL

  C->>F: Ver lista de pendientes de facturar
  F->>API: GET /api/v1/contabilidad/facturas/pendiente-facturar/
  API->>DB: Cargas confirmadas sin factura
  DB-->>API: Lista de pendientes
  API-->>F: [{tipo, id, cliente, monto...}]
  F-->>C: Muestra pendientes

  C->>F: Selecciona ítem, ingresa Nro. Factura
  F->>API: POST /api/v1/contabilidad/facturas/emitir/
  API->>SVC: emitir_para_origen(tipo,id,nro_factura)
  SVC->>DB: BEGIN TRANSACTION
  SVC->>DB: SELECT origen FOR UPDATE (of self)
  SVC->>DB: Verifica origen sin factura previa
  SVC->>DB: Resuelve cliente (cliente_origen o tarjeta→hijo→cliente)
  SVC->>DB: Calcula IVA (monto*10/110)
  SVC->>DB: INSERT Factura(nro, monto, iva_10)
  SVC->>DB: UPDATE origen.factura = factura
  DB-->>SVC: Commit OK
  API-->>F: 201 {factura_id, nro_factura}
  F-->>C: ✅ Factura emitida correctamente

SEQ-08 · Secuencia — Cierre de Caja

contabilidad
Al final del día, el cajero cuenta el efectivo físico y cierra la caja. El sistema calcula la diferencia entre el monto esperado (sumatoria de movimientos) y el contado, y genera el PDF de cierre.
sequenceDiagram
  actor C as 🧑‍💼 Cajero
  participant F as Frontend
  participant API as Django API
  participant SVC as CajaService
  participant DB as PostgreSQL

  C->>F: Ingresa monto contado físico
  F->>API: POST /api/v1/contabilidad/cierres-caja/{id}/cerrar/
  API->>SVC: cerrar_caja(cierre, monto_contado)
  SVC->>DB: BEGIN TRANSACTION
  SVC->>DB: SELECT CierreCaja FOR UPDATE
  SVC->>DB: Verifica estado = ABIERTO
  SVC->>DB: SUM(MovimientoCaja.monto) por tipo
  SVC->>DB: Calcula diferencia efectivo
  SVC->>DB: UPDATE CierreCaja(estado=CERRADO, diferencia, fecha_cierre)
  DB-->>SVC: Commit OK
  SVC-->>API: CierreCaja actualizado
  API-->>F: 200 {cierre_id, diferencia, totales_por_medio}
  F-->>C: ✅ Caja cerrada

  C->>F: Solicita imprimir PDF
  F->>API: GET /api/v1/contabilidad/cierres-caja/{id}/pdf/
  API->>DB: Carga cierre + movimientos
  API-->>F: HTML con datos del cierre
  F->>F: window.print()
  F-->>C: 🖨 PDF del cierre generado
